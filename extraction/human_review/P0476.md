### Evidence (quotes with section/page) — required
- "Some works
have studied the impact of developer experience and use metrics
to study the relationship with the maintainability and evolution of

- "In this systematic mapping, we present a catalog of met-
rics that have been used to quantify developers’ experience, found
in 34 works"

- "These metrics are classified by the type of experience
they represent and the purpose of using them. The results showed
that most of the selected studies use metrics based on counting
developer activities in code"

- "We considered the following inclusion (I) and exclusion (E) criteria
to select the studies:
•I1: The study presents at least one metric to quantify devel-
oper experience.
•E1: The metric is not explicitly defined.
•E2: The study is not in English.
•E3: The study is not in the Software Engineering area.
•E4: The study is not a conference paper, workshop, or journal
article.
•E5: The work is not a primary study.
•E6: There is a new version of the study."


- "•RQ1: What metrics are used to measure developer experi-
ence in Software Engineering?
•RQ2: What data is used to measure developer experience?
•RQ3: What subjects are addressed with developer experi-
ence?
•RQ4: What experience category is measured?
•RQ5: What is the goal of the studies that measure developer
experience?"


- "The results indicate that developer experience is measured differ-
ently by Software Engineering studies. The most usual approaches
are to measure the experience based on the ratio of commits or the
proportion of lines changed by a developer compared to the others.
This information is obtained from the version control systems (for
instance, Git or SVN)."


- "The most frequent data used to
measure developer experience is the number of commits (14; 26%),
the number of lines of code that were modified (code churn – 12;
22%), and seniority (8; 15%). Seniority in this context means how
much time of experience (e.g., months, years) the developer has.
Other data used by the metrics are information from social coding
platforms, such as Stack Overflow (e.g., reputation) and GitHub
(e.g., number of repositories); bug report, comments in code review;
the number of files modified, and others (for instance, the time
needed to perform a task)"


- "This RQ presents the subjects that are discussed by the studies that
use software developer experience metrics. To answer this research
question, we synthesized the data collected in D13 (Table 1) organiz-
ing them into the topics identified during the data analysis process.
We found the following concepts and subjects being discussed as
research themes and questions in the studies about developer expe-
rience: mining software repository, defect prediction model, code
and architecture problems, process metrics, developer activities
and characteristics, task allocation (developer recommendation),
algorithms and approaches to estimate truck factor4 (bus factor,
lottery number), expert identification (in components, methods, or
bug fixing), bug triaging, knowledge dissemination, and learning
software development"

- "The categories identified are: project (not
only code), software engineering (and its processes), programming
(writing code in several programming languages), bug fixing, spe-
cific programming language, and code (a component, file, method,
or an entire project). Most of the metrics (19; 58%) measured the
code experience, followed by the experience in bug fixing (4; 12%)
and experience in programming (4; 12%), two (6%) metrics quanti-
fied the experience in specific programming languages and also two
considered experience in a software project. Only one (3%) metric
considered the experience in Software Engineering, and another
(3%) measured the experience in specific software libraries."

- "Half of the 34 selected studies had as one of their goals presenting
a new measuring approach. Nine studies used experience metrics to
investigate software quality (e.g., from software bugs). Four studies
used metrics to study defect prediction models, what is used, among
other things, to estimate the cost in releases. Three studies analyzed
human factors (developer characteristics) in software development
(for instance, the profile of who works in open-source projects).
Eight studies correspond to other goals - for instance, one work
presents an approach to summarize the developer activity from the
information available in GitHub [41], or the empirical investigation
of the effects of file editing patterns on software [46]."

-"Most developers’ experience metrics (17) are based on counting
(for instance, counting the number of commits, number of files, or
number of lines of code). Metrics based on different approaches
use information from social coding platforms [18, 34, 44] and time
(in months or years) [3, 4, 6, 21, 41, 44, 48], for example. However,
this result may be due to the availability of data and not because
that they capture the experience better. In these metrics, developer
activities can be easily retrieved by mining software repositories."
