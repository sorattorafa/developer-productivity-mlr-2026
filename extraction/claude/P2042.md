## Objetivo

Tratar o problema de alcancar um nivel apropriado de dependencia (reliance) de IA em engenharia de software, propondo um reliance-control framework preliminar a partir de 22 entrevistas com desenvolvedores que usam LLMs. O framework relaciona o nivel de controle humano sobre a IA ao nivel de reliance e serve para identificar overreliance e underreliance. Os autores ampliam a definicao de "Appropriate Level of Reliance on AI" para alem de accuracy, como "the extent to which one should rely on AI tools, encompassing different levels of reliance, from self-reliance to full reliance on AI (i.e., full automation) and different levels of control from self-control to losing control over AI", e derivam implicacoes para pratica, educacao e pesquisa.

### Frameworks Propostos
**Reliance-Control Framework on AI for SE** (Figure 1): grade bidimensional com eixo de controle humano (self-control → taking control → balanced control → handing over control to AI → losing control) e eixo de reliance (self-reliance → reliance on colleagues → appropriate reliance → overreliance → full automation). O "sweet spot" e a interseccao entre balanced control e appropriate reliance (ponto 7). Exemplos praticos ilustrativos derivados das entrevistas:
1. Self-control/self-reliance: desligar o autocomplete do GitHub Copilot ao aprender linguagens.
2. Self-control/reliance on colleagues: pair programming tradicional.
3. Self-control/appropriate reliance: LLM apenas para information retrieval.
4. Taking control/self-reliance: consultar o LLM so depois de tentar sozinho; migrar do Copilot para o Claude no browser.
5. Taking control/reliance on colleagues: discutir abordagens organizacionais com colegas.
6. Code generation via chat em pagina web.
7. Balanced control/appropriate reliance: TDD com agent mode, com testes gerados e melhorados pelo desenvolvedor; prompting em multiplos LLMs.
8. Handing over control/overreliance: prototipar UI via Agent Mode, geracao de grandes blocos de codigo, nao checar informacao em fontes externas.
9. Handing over control/full automation: boilerplate e comentarios via Cursor Agent Mode; resumo de reunioes.
10. Losing control/overreliance: geracao de PRs via Copilot Agent Mode; full stack via Cursor Agent Mode.
11. Losing control/full automation: mudancas multi-arquivo via Cursor agent mode.

A Table 3 classifica os tipos de interacao de Treude e Gerosa. Exemplos: conversational assistance e explicit UI actions = taking control/appropriate reliance; selection-based enhancements e comment-guided prompts = balanced control/appropriate reliance; contextual recommendations, auto-complete e file-aware suggestion = handing over control/overreliance–full automation; event-based triggers e automated API responses = handing over control/full automation.

## Fatores que Influenciam Produtividade

### Fatores Positivos
| Fator | Categoria |
|-------|-----------|
| Uso de IA com balanced control e appropriate reliance (ex.: TDD com agent mode supervisionado) | Process / Human |
| LLMs para information retrieval e sumarizacao (menos esforco do que pesquisar em varias paginas) | Technical |
| Automacao de tarefas repetitivas (boilerplate, traducao de codigo, resumo de reunioes) | Technical |
| Reducao de esforco e tempo de desenvolvimento com ferramentas de IA (citando [16]) | Technical |
| Ferramentas integradas ao ambiente de desenvolvimento reduzem a ambiguidade do contexto | Technical |

### Fatores Negativos
| Fator | Categoria |
|-------|-----------|
| Overreliance em IA: atrofia de pensamento critico, perda de entendimento do codigo e do fluxo, dependencia de IA para depurar | Human |
| Losing control: agent mode alterando multiplos arquivos e secoes criticas, inserindo bugs ou vulnerabilidades | Technical |
| Hallucinations quando a informacao nao e verificada em fontes oficiais | Technical |
| Underreliance: privar-se de ganhos potenciais de produtividade e qualidade | Human |
| Reducao de comunicacao do time em questoes criticas (citando Khojah et al. [11]) | Organizational / Human |
| Context switching entre IDE e LLM no browser (no modo "taking control") | Process |
| Ferramentas que exigem mais controle podem parecer reduzir a produtividade ("tools that only slow them down") | Technical / Human |

## Resultados Principais

- Controle e reliance emergiram como conceitos proeminentes na analise STGT de 22 entrevistas.
- Cinco graus de controle (Table 1) e cinco graus de reliance (Table 2) foram caracterizados, com exemplos.
- O ponto otimo ("sweet spot") e a combinacao de balanced control com appropriate reliance, exemplificada por TDD com agent mode supervisionado.
- Formas de interacao oferecem niveis diferentes de controle: chatbots online (ChatGPT, Claude) mantem alto controle, mas exigem fornecer todo o contexto; agent mode (Cursor, Windsurf) cede controle e aumenta o risco de erros e vulnerabilidades; Claude Code no terminal e apresentado como meio-termo (balanced control), a ser validado experimentalmente.
- Implicacoes para pratica: selecionar ferramentas conforme a expertise do time (novatos usarem modos que exigem mais controle); definir normas de uso de IA no time e incluir reflexao sobre padroes de reliance em retrospectivas.
- Implicacoes para educacao: restringir ambientes assistidos por IA para estudantes de 1o e 2o ano e introduzir plataformas AI-driven e seus riscos no ultimo ano.

## Desafios do Uso das Metricas

- O artigo nao trata de metricas de produtividade. Desafios relacionados: equilibrar controle, reliance e produtividade, ja que desenvolvedores podem nao adotar ferramentas que so os atrasam; "how to induce appropriate reliance is still open" (citando Bo et al.).
- Intervencoes da literatura para calibrar reliance (frictions, disclaimers, uncertainty highlighting) tiveram efeitos colaterais (queda no click rate) ou nao melhoraram a appropriate reliance.
- O nivel adequado de reliance varia por tarefa, capacidade da ferramenta e expertise do desenvolvedor.

## Limitacoes

- O grau de controle e reliance nao se limita aos exemplos apresentados; os exemplos sao "merely illustrative and not meant to be exhaustive".
- Potencial research bias, comum em pesquisa qualitativa.
- Tamanho de amostra limitado.
- Expertise do desenvolvedor nao foi considerada no framework bidimensional.
- O framework e preliminar; recomenda-se validar e expandir com case studies e experimentos, comparar ferramentas com diferentes interacoes e validar o papel do Claude Code no terminal.

## Contribuicao Principal

O artigo propoe o primeiro reliance-control framework (segundo os autores) para trabalho de SE apoiado por IA. O framework e bidimensional, cruza cinco niveis de controle humano com cinco niveis de reliance e identifica um "sweet spot" de balanced control com appropriate reliance. Foi derivado de 22 entrevistas analisadas com STGT. Tambem amplia a definicao de appropriate reliance on AI, mapeia a taxonomia de interacoes developer-AI de Treude e Gerosa no framework e oferece orientacoes para lideres (selecao de ferramentas, normas de time, retrospectivas), educadores e pesquisadores.
