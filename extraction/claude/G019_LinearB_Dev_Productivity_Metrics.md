## Objetivo
Apresentar 21 metricas de produtividade do desenvolvedor que lideres de engenharia deveriam
acompanhar, organizadas em tres dimensoes ("tres Es": eficiencia, efetividade, experiencia),
argumentando contra metricas de output puro (linhas de codigo) e a favor de uma visao
multifacetada que inclui bem-estar e alinhamento com objetivos de negocio.

---

## Frameworks e Metricas

### Frameworks Mencionados
- DORA (as quatro metricas incluidas na lista)
- Modelo proprio das "tres dimensoes": Eficiencia, Efetividade, Experiencia
- (SPACE nao e mencionado; "cognitive load" aparece como metrica de eficiencia, eco do vocabulario DevEx, mas sem o framework DevEx formal)

### Metricas Propostas/Discutidas (21, por dimensao)
- **Eficiencia:** Cycle Time, PR Maturity, PR Size, Code Churn/Rework, Stability (CFR + MTTR), Cognitive Load, Task Completion.
- **Efetividade:** Alignment with Business Goals, Resource Allocation, Accuracy Scores (Planning/Capacity), Meaningful Contributions, Consistency, Balancing New Value vs Maintenance.
- **Experiencia:** Idle/Wait Time, Meeting Team Goals, Task Balance, Skill Expansion, Knowledge Expansion, Coding vs Code Review, Unplanned/Added Work, WIP (evitar burnout).

## Principais Contribuicoes
- Estrutura 21 metricas num modelo de tres dimensoes (eficiencia/efetividade/experiencia),
  integrando DORA, leading indicators e investimento.
- Inclui explicitamente a dimensao de experiencia/bem-estar (cognitive load, burnout, WIP,
  satisfacao) como parte da produtividade.
- Recomenda uso das metricas em definicao de metas (OKRs/SMART), automacao e rituais de time
  (1:1s, stand-ups, performance reviews com dados + surveys de sentimento).
